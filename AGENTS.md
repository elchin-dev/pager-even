# AGENTS.md — Правила разработки `smartglasses_pager`

Этот файл задаёт обязательные архитектурные, UX- и security-правила для всех агентов и разработчиков, работающих с `server/` и `plugin/`.

## 1. Структура репозитория
- `server/` — Node.js + TypeScript + Hono + grammY + Drizzle ORM (SQLite) + Gemini (`gemini-3.5-flash-lite`), деплой в Docker на Railway с `ffmpeg`.
- `plugin/` — Vite + TypeScript + `@evenrealities/even_hub_sdk` для очков **Even Realities G2** и симулятора `evenhub-simulator`.
- `docs/SPEC.md` — актуальная функциональная спецификация.

## 2. Неприкосновенные продуктовые ограничения
- **Голосовой ответ в чат (`POST /api/msg/:id/voice`):** остаётся сырым голосовым сообщением (PCM → WAV → OGG/Opus через `ffmpeg` в памяти → `sendVoice`), **без расшифровки и без ИИ**.
- **Расшифровка СВОЕГО голоса (STT):** разрешена **только** для:
  1. Голосовых заметок,
  2. Брифа встречи (добавление в описание события Google Calendar).
- **Дайджест каналов:** парсится **только** через публичную веб-страницу `https://t.me/s/<channel>`. **Без** входа в Telegram-аккаунт и **без** MTProto.
- **Роль Telegram-бота:** бот управляет заметками, подписками на каналы, подключением Google Calendar и настройками уведомлений. **Бот НЕ дублирует обычные входящие сообщения Telegram** (личные сообщения приходят через Telegram Business и отображаются на очках).
- **Изменения Google Calendar (создание, перенос, добавление брифа):** выполняются **только после явного тапа** пользователя и **обязательно с окном отмены 3 секунды** (двойной тап отменяет действие до отправки запроса в Google Calendar API).
- **Защита быстрых ответов от конфликта с календарём (обязательно):**
  1. До вызова ИИ сервер проверяет события Google Calendar и передаёт в промпт точный статус (`BUSY` / `FREE`) и список занятых интервалов на ближайшие 72 часа.
  2. При наличии конфликта (`proposed.isFree === false`) код **принудительно вырезает** любые утвердительные варианты и варианты со словом «свободен» (`"Да, давай…"`, `"Да, свободен…"`, `"Хорошо…"`), оставляя только ближайшее свободное окно и безопасный отказ/отсрочку.
  3. Предложение создать встречу показывается на очках **только после** отправки утвердительного ответа (не вместо сообщения).

## 3. Жёсткие лимиты Even Hub SDK и экранов
- **Строка элемента списка (`ListItemContainerProperty.itemName`):** строго **`<= 63` байт UTF-8** (кириллица = 2 байта/символ, эмодзи = 4 байта/символ). Превышение вызывает отказ `RebuildPageContainer` / `CreateStartUpPageContainer`.
- **Пункт контекстного меню (`MenuItemProperty.itemName`):** строго **`<= 32` байт UTF-8**.
- **Контейнеры на странице:** не более `3` контейнеров, ровно один контейнер с `isEventCapture: 1`.
- **Шрифт LVGL:** спецсимволы `✓`, `⚠`, `▸` могут отсутствовать во встроенном шрифте прошивки/симулятора (`glyph dsc. not found`). Всегда проверять отображение в `evenhub-simulator` и при необходимости заменять на безопасный ASCII (`!`, `*`, `>`, `-`).
- **Быстрые ответы:** от **1 до 4** вариантов (сколько уместно по контексту) + всегда последним пунктом **`Пропустить`**. Каждый вариант `<= 32` символов, в Telegram отправляется **ровно показанный текст** (`text === lens` символ в символ).
- **Порядок отображения:** во всех списках и в истории переписки **новое всегда сверху** (обратная хронология).
- **Карточка встречи:** сначала название события, под ним время. Приписка `«через N мин»` показывается **только** если до начала встречи осталось **меньше 60 минут**.

## 4. Приватность, хранение и логирование
- **Запрещено логировать:** тексты входящих и исходящих сообщений, расшифровки голосовых, содержимое заметок, названия и описания встреч, токены устройств, OAuth-токены и API-ключи. В логах допустимы только ID, тип события, статусы, длительность в секундах и коды ошибок.
- **Запрещено сохранять аудио:** ни на диск, ни в БД, ни во временные файлы. Любое транскодирование (`ffmpeg`) и STT/описание медиа выполняются строго в памяти (`Buffer` через `stdin`/`stdout`).

## 5. Gemini и окружение
- Модель по умолчанию: `gemini-3.5-flash-lite` (не передавать `thinkingConfig: { thinkingBudget: 0 }`, иначе HTTP 400).
- На локальной машине разработчика `ffmpeg` может отсутствовать — во всех серверных тестах транскодирование (`transcodeWav`, `transcodeMediaToWav`) должно инжектироваться/мокаться.
- Перед коммитом обязательно проверять:
  - `cd server && npm run typecheck && npm run build && npm test`
  - `cd plugin && npm run build`
