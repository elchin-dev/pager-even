# Pager — спецификация MVP (v3, 24.11.2026)

> Рабочее название. Треки: **01 Messaging & News** + **04 AI Assistants & Work**, спецприз **Best Telegram integration**.
> v2: добавлен гибрид ИИ (серверный ключ по умолчанию + Bring Your Own Key), адаптер провайдеров, grammY.
> v3: добавлен Флоу D «Проекты и отложенные приглашения» (ожидание человека + подтверждение на линзе).

## 1. Концепция в одной фразе

**AI-пейджер для Telegram на очках G2:** показывает только сообщения, которые требуют реакции, одной строкой на линзе, и даёт ответить за секунду: тапом по готовому AI-черновику, с учётом твоего Google Calendar, или короткой фразой голосом, которую ИИ превращает в нормальный ответ.

Питч для жюри: *«Прочитал — ответил — не достал телефон».*

### Чем отличаемся от существующих G2-приложений для Telegram
В экосистеме уже есть читалки/диктовалки (TeleGlance, even-messages, even-bridge и т.д.). Они переносят чат на очки «как есть». Pager делает другое:
1. **Триаж:** ИИ отсеивает шум, на линзу попадает «что нужно сделать», а не поток.
2. **Ответ в 1 тап:** 3 коротких черновика вместо диктовки.
3. **Межсервисное действие:** «Встретимся завтра?» → проверка Calendar → ответ со слотом + создание события.
4. **Официальный Telegram Business Bot API**, а не MTProto-сессия пользователя: мы не храним доступ к аккаунту, пользователь сам выбирает чаты и отключает бота в настройках Telegram.
5. **Свой ИИ по желанию:** работает из коробки, но можно подключить свой ключ Claude / Gemini / ChatGPT.

## 2. MVP: три флоу Read & Write

### Флоу A: Триаж + ответ в 1 тап (ядро, обязателен)
1. Собеседник пишет в личку → бот получает `business_message` (webhook).
2. Бэкенд → LLM: приоритет, суть ≤ 40 символов, интент, 3 черновика на языке собеседника + версия для линзы ≤ 32 символов.
3. Пользователь открывает Pager → **Inbox** (только «нужен ответ», сверху срочные).
4. Тап → **Card**: кто, суть, 3 черновика. Свайп выбирает, тап отправляет (окно отмены 3 сек).
5. Отправка от имени пользователя: `sendMessage` + `business_connection_id`.

```
INBOX                               CARD
┌──────────────────────────────┐    ┌──────────────────────────────┐
│PAGER · 3 need reply          │    │Aziz K. · urgent              │
│> ! Aziz K.  KP by 17:00?     │    │Asks for the KP by 5pm today  │
│    Mom      Call tonight?    │    │> Yes, sending by 17:00       │
│    Dilnoza  Meet tomorrow?   │    │  Tomorrow morning ok?        │
│                              │    │  Will call you in 10 min     │
└──────────────────────────────┘    └──────────────────────────────┘
```

### Флоу B: Ответ с учётом календаря (вау-момент трека 04)
1. LLM помечает интент `schedule` («встретимся/созвонимся/когда удобно»).
2. Бэкенд берёт события из Google Calendar на 3 дня → считает 2–3 свободных слота в рабочие часы.
3. Черновики строятся из слотов: «Tomorrow 15:00 works», «Thu 11:00?».
4. Тап → отправка ответа **+ создание события** в Calendar («Meeting: Dilnoza»).
```
┌──────────────────────────────┐
│Dilnoza · meeting             │
│Free tomorrow afternoon?      │
│> Tomorrow 15:00 works  +cal  │
│  Tomorrow 17:00?       +cal  │
│  Thu 11:00 better?           │
└──────────────────────────────┘
```

### Флоу C: Голосовой ответ с AI-полировкой
1. На Card: **долгий тап** (push-to-talk) или пункт меню «Voice reply».
2. PCM с микрофона G2 → WAV → бэкенд → STT → LLM: «скажи да, но после обеда» → «Yes, after lunch works — around 14:00?».
3. Экран: полированный черновик → тап отправить, двойной тап отмена.
```
┌──────────────────────────────┐
│● Listening… release to stop  │
└──────────────────────────────┘
┌──────────────────────────────┐
│You said: yes but after lunch │
│> Yes, after lunch, ~14:00?   │
│  tap send · 2×tap cancel     │
└──────────────────────────────┘
```

### Флоу D: Проекты и отложенные приглашения («добавь, когда появится»)

**Задача пользователя:** «Создай чат проекта Alpha и добавь туда Азиза и Дилнозу». Если человека ещё нет в доступных чатах, Pager ждёт его и, когда тот появится, спрашивает на линзе: «Азиз написал. Добавить в Alpha?».

**Ограничение Telegram (проверено по changelog Bot API до 10.5):** бот **не может** создать группу или канал и **не может** добавить человека в чат напрямую. Он может: быть админом в группе/канале, создавать invite-ссылки (`createChatInviteLink`, в т.ч. с `creates_join_request`), одобрять заявки (`approveChatJoinRequest` / `declineChatJoinRequest`) и писать от имени пользователя через business-подключение (только в чаты, где есть право ответа). Поэтому механика такая:

**1. Проект = группа или канал, где наш бот админ (один раз, на телефоне).**
- Голосом или в боте: «New project Alpha» → бот присылает кнопку-диплинк «Add Pager to a group» (`t.me/<bot>?startgroup=alpha&admin=invite_users`) и такую же для канала (`startchannel`). Пользователь выбирает существующую группу или создаёт новую в Telegram и добавляет туда бота.
- Бот получает `my_chat_member` → сохраняет проект `{chat_id, title, type}` и проверяет право `can_invite_users`. Линза: «Project Alpha ready ✓».
- Создание группы с линзы невозможно без MTProto-сессии аккаунта. Это сознательный выбор ради безопасности (см. §7), и это первый пункт в feature requests к Telegram/Even.

**2. Команда «добавить человека» (голосом, из меню или из входящего сообщения).**
- Голос (через пайплайн Флоу C): «add Aziz to Alpha» → LLM возвращает интент `{type:"invite", person:"Aziz", project:"Alpha"}`.
- Из входящего сообщения: «Can you add me to the Alpha chat?» → триаж ставит интент `invite`, и один из черновиков становится действием `Invite to Alpha`.
- Поиск человека в `contacts` (все, кто писал пользователю через business-подключение): точное совпадение по @username → иначе по имени (fuzzy). Несколько кандидатов → выбор на линзе.

**3. Если человек найден и есть право ответа** → карточка подтверждения:
```
┌──────────────────────────────┐
│Invite to Alpha?              │
│Aziz K. (@aziz_k)             │
│> Yes, send invite            │
│  No                          │
└──────────────────────────────┘
```
Тап → бот создаёт персональную invite-ссылку с `creates_join_request=true` (имя ссылки = id задачи) → от имени пользователя уходит сообщение «Join the Alpha project chat: <link>» → когда приходит `chat_join_request` от **ожидаемого** `user_id` по этой ссылке, бот одобряет автоматически. Заявки от кого-то другого по этой ссылке не одобряются, а попадают на линзу как вопрос.

**4. Если человека нет (не писал, нет права ответа)** → создаётся отложенная задача `waiting`:
```
┌──────────────────────────────┐
│Waiting for Aziz              │
│Will ask when he writes       │
│> OK                          │
│  Cancel                      │
└──────────────────────────────┘
```
- Каждое новое `business_message` проверяется против активных задач (username → имя). Совпадение → задача `ready` и **поднимается первой строкой в Inbox**:
```
┌──────────────────────────────┐
│PAGER · 1 task · 2 need reply │
│> ★ Aziz is here → Alpha?     │
│    Mom      Call tonight?    │
└──────────────────────────────┘
```
  Тап → карточка подтверждения из п.3 (с текстом его сообщения, чтобы было видно, что это тот самый человек).
- Задача живёт 7 дней, потом `expired` (уведомление в боте). Отмена: двойной тап на карточке или `/tasks` в боте.
- Список задач: пункт меню «Tasks» на линзе (≤ 5 строк: `Aziz → Alpha · waiting`).

**Правила безопасности для Флоу D:** приглашение уходит только после тапа; ссылка персональная, с join request и сроком жизни 7 дней; автоматически одобряется только ожидаемый `user_id`; бот не получает права удалять участников.

**Приоритет:** после A и B. Минимальная версия (если не хватает времени): только приглашение из входящего сообщения + ожидание по @username, без голосовой команды и без выбора из нескольких кандидатов.

### Вне MVP (только если останется время)
Бриф при открытии («3 need reply · 1 meeting in 20 min»), Notion/Drive как база знаний для черновиков, Gmail, групповые чаты.

## 3. Карта жестов (тачпад на дужке = кольцо R1)

| Экран | Свайп ↑/↓ | Тап | Двойной тап | Долгий тап |
|---|---|---|---|---|
| Inbox | перемещение по чатам | открыть Card | выход (`shutDownPageContainer(1)`) | — |
| Card | выбор черновика | отправить (окно отмены 3 с) | назад / пропустить | голос (удерживать) |
| Sending | — | — | **отмена** | — |
| Voice result | — | отправить | отмена | перезаписать |

ОС может перехватить «тап + удержание» для системного контекстного меню, поэтому голос дублируется пунктом в `menuObject` («Voice reply», «Skip», «Refresh»).

## 4. Раскладка экрана (576×288)

- Шапка: text-контейнер, y=0, h≈44: «кто · приоритет».
- Суть: text-контейнер, y≈44, h≈70: 1–2 строки.
- Действия: **list-контейнер** (нативная подсветка и прокрутка, до 20 пунктов × 64 символа), `isEventCapture: 1`.
- Итого 3 контейнера (симулятор принимает не больше 4).
- Обновления текста через `textContainerUpgrade`, смена экрана через `rebuildPageContainer` (меню пересылать каждый раз).
- В документированном шрифте нет кириллицы, неподдерживаемые символы молча пропадают → **слой транслитерации** для линз (ru/uz-кириллица → латиница). В Telegram уходит оригинал. Демо снимаем на английском.

## 5. Архитектура

```
 Telegram (собеседник)                          Google Calendar API
        │ личное сообщение                               ▲
        ▼                                                │ refresh token (AES-GCM)
 Telegram Bot API ──webhook (secret header)──►  ┌─────────────────────────┐
        ▲                                        │ Backend (Node+Hono+TS)  │
        │ sendMessage(business_connection_id)    │ • grammY bot            │◄─► AI adapter:
        └────────────────────────────────────────│ • triage / drafts       │    Anthropic | Gemini |
                                                 │ • calendar slots        │    OpenAI | OpenRouter
  Браузер: Google OAuth + ввод своего AI-ключа ─►│ • STT adapter           │    (серверный ключ или BYOK)
                                                 │ • pairing / auth        │◄─► STT: Groq/OpenAI Whisper
                                                 │ SQLite (Drizzle)        │
                                                 └──────────▲──────────────┘
                                                            │ HTTPS + Bearer deviceToken (+ SSE)
                                   ┌────────────────────────┴────────────┐
                                   │ Plugin: Vite + TS + even_hub_sdk     │
                                   │ (WebView в Even Realities App)       │
                                   │ • state machine экранов              │
                                   │ • буфер PCM → WAV                    │
                                   │ • phone UI: статус, кнопка pairing   │
                                   └────────────────┬─────────────────────┘
                                                    │ BLE (SDK)
                                                 Even G2 / R1
```

### Стек
- **Plugin:** шаблон `evenhub-templates/minimal` (+ куски из `asr`), Vite + TypeScript, без фреймворка.
- **Backend:** Node 20 + TypeScript + Hono, grammY (Telegram), SQLite (better-sqlite3) + Drizzle, zod. Деплой на Railway с volume и постоянным HTTPS-доменом.
- **AI:** адаптер провайдеров (см. §6). По умолчанию Claude Haiku на серверном ключе.
- **STT:** адаптер; по умолчанию Whisper через Groq (OpenAI-совместимый endpoint).

### Почему ИИ на сервере, а не в очках
- Telegram шлёт webhook на сервер, пока плагин закрыт → триаж делается **в момент прихода**, при открытии всё уже готово (на очках важна мгновенность).
- Текст сообщений и так проходит через сервер → ИИ в клиенте не даёт выигрыша в приватности.
- На очках ключ не ввести, а хранить его в WebView localStorage — слабое место.
- Жюри должно запустить приложение без своего ключа.

### Сопряжение (Pairing Code) и авторизация
1. Плагин при первом запуске: `POST /api/pair/start` → `{pairId, code: "482913"}`. Линза: `Send 482913 to @PagerG2Bot`. Телефонный UI плагина: кнопка-диплинк `t.me/<bot>?start=482913` (если WebView не откроет, вводим код вручную).
2. Бот получает `/start 482913` → связывает Telegram-пользователя с устройством. Код живёт 10 минут, одноразовый.
3. Плагин опрашивает `GET /api/pair/status?pairId=` → получает `deviceToken` → хранит в localStorage. В БД только SHA-256-хэш.
4. Бот присылает инструкцию: «Профиль → Изменить → Автоматизация чатов (Chat Automation) → @бот → выбрать чаты и разрешить ответы». Без Premium это работает именно там; у Premium/Business-аккаунтов то же самое в Settings → Telegram Business → Chatbots. Приходит `business_connection` → сохраняем `connection_id`, `rights`.
5. `/google` в боте → одноразовая ссылка → **обычный браузер** → Google OAuth (scope `calendar.events`), `state` одноразовый → refresh token шифруется AES-256-GCM.
6. `/ai` в боте → одноразовая ссылка на страницу настроек ИИ (§6).
7. `/unpair` отзывает токен устройства и удаляет Google-токены и AI-ключи.

### API бэкенда
| Метод | Назначение |
|---|---|
| `POST /tg/webhook` | апдейты бота; проверка `X-Telegram-Bot-Api-Secret-Token` |
| `POST /api/pair/start`, `GET /api/pair/status` | сопряжение |
| `GET /api/inbox` | список «нужен ответ», уже с транслитом и обрезкой |
| `GET /api/msg/:id` | карточка: суть, черновики, слоты |
| `POST /api/msg/:id/send` | `{draftIndex}` или `{text}`, `createEvent?` |
| `POST /api/msg/:id/skip` | пометить «просмотрено» |
| `POST /api/voice?msgId=` | WAV → `{transcript, polished}` |
| `GET /api/stream` | SSE: новые сообщения, пока плагин открыт |
| `GET /auth/google/start?t=`, `/auth/google/callback` | OAuth в браузере |
| `GET/POST /settings/ai?t=` | страница выбора провайдера и ввода своего ключа |
| `GET /api/tasks` | отложенные задачи (waiting/ready) |
| `POST /api/tasks` | создать задачу `{type:"invite", person, projectId}` (из голоса/меню) |
| `POST /api/tasks/:id/confirm`, `/decline` | подтверждение на линзе → invite-ссылка + сообщение от имени пользователя |
| `GET /api/projects` | проекты (группы/каналы, где бот админ) |

Бот дополнительно обрабатывает апдейты `my_chat_member` (бота добавили/удалили в группе или канале) и `chat_join_request`; команды `/project <name>`, `/tasks`.

### Модель данных (SQLite)
- `users` (id, tg_user_id, tg_name, business_connection_id, business_rights_json, tz, created_at) — с Bot API 9.0 вместо `can_reply` приходит объект `rights` (BusinessBotRights)
- `contacts` (id, user_id, tg_user_id, name, username, last_message_at) — все, кто писал пользователю через business-подключение
- `projects` (id, user_id, chat_id, title, type: group|channel, can_invite, created_at)
- `tasks` (id, user_id, type: invite, person_query, target_tg_user_id NULL, project_id, status: waiting|ready|sent|done|declined|expired, invite_link NULL, created_at, expires_at)
- `devices` (id, user_id, token_hash, created_at, revoked_at)
- `pair_codes` (code, pair_id, user_id NULL, expires_at, used_at)
- `link_tokens` (token_hash, user_id, purpose: google|ai, expires_at, used_at)
- `google_accounts` (user_id, email, refresh_token_enc, scope)
- `ai_settings` (user_id, mode: server|byok, provider: anthropic|gemini|openai|openrouter, model, key_enc NULL, key_last4)
- `messages` (id, user_id, chat_id, tg_message_id, from_name, text, received_at, status: new|seen|replied|skipped, ai_json, expires_at)
- `actions` (id, message_id, type: reply|event, payload, created_at)

## 6. ИИ: гибрид «серверный ключ + BYOK»

- **По умолчанию:** серверный ключ (env), модель Claude Haiku. Демо и проверка жюри работают сразу.
- **BYOK:** пользователь в боте пишет `/ai` → одноразовая ссылка (10 мин) → веб-страница: провайдер (Claude / Gemini / ChatGPT / OpenRouter), модель, ключ → кнопка «Проверить» (тестовый запрос) → сохранить.
  - Ключ шифруется AES-256-GCM, в UI показываются только последние 4 символа, ключ никогда не логируется и не отдаётся обратно клиенту.
  - Ключ **не принимаем через чат бота** (останется в истории Telegram).
  - `/deletekey` удаляет ключ и возвращает режим server.
  - Если BYOK-ключ падает (401/429) → сообщение в боте + временный фолбэк на серверный ключ с лимитом.
- **Адаптер:**
```ts
interface LlmProvider {
  id: 'anthropic' | 'gemini' | 'openai' | 'openrouter'
  completeJson<T>(opts: { system: string; user: string; schema: ZodSchema<T>; maxTokens?: number }): Promise<T>
}
function getProviderForUser(userId): LlmProvider // ai_settings → BYOK или серверный
```
  Реализации тонкие, через `fetch` (без тяжёлых SDK), JSON-режим каждого провайдера + zod-валидация.
- **STT-адаптер:** `transcribe(wav: Uint8Array, langHint?)`. Серверный — Groq Whisper. С BYOK OpenAI — Whisper OpenAI, с BYOK Gemini — аудио в Gemini. С BYOK Anthropic — STT остаётся серверным (у Claude нет STT).
- **Бизнес-модель:** Free (свой ключ) / Pro $5–8 в месяц (наш ключ, лимиты выше).

### Контракт LLM (триаж)
Вход: последние 3–5 сообщений чата, имя, текущее время/таймзона, свободные слоты (если интент schedule). Выход строго JSON:
```json
{
  "priority": "urgent|needs_reply|fyi|ignore",
  "intent": "reply|schedule|info",
  "gist": "Asks for the KP by 5pm today",
  "lang": "ru",
  "drafts": [
    {"text": "Да, пришлю до 17:00", "lens": "Yes, sending by 17:00", "slot": null},
    {"text": "Можно завтра утром?", "lens": "Tomorrow morning ok?", "slot": null},
    {"text": "Наберу через 10 минут", "lens": "Will call you in 10 min", "slot": null}
  ]
}
```
`text` уходит в Telegram, `lens` показывается на очках (латиница, ≤ 32 символа). Валидация через zod; при невалидном ответе 1 ретрай, потом фолбэк без ИИ.

### Голос (клиент)
`audioControl(true, Glasses)` на начало удержания → копим `audioEvent.audioPcm` (s16le, 16 kHz, mono, чанки по 100 мс) → на отпускании `audioControl(false)` → 44-байтный WAV-заголовок → `POST /api/voice`. Лимит 15 с. В симуляторе — микрофон компьютера (`--aid`).

## 7. Безопасность
- Все серверные ключи только в env бэкенда; `.env.example` в репо, `.env` в `.gitignore`; в `plugin/` нет ни одного секрета.
- Нет MTProto-сессии: только Business-подключение, видимое и отзываемое в Telegram.
- Device token: 32 случайных байта, в БД SHA-256; отзыв `/unpair`.
- Google refresh token и BYOK-ключи: AES-256-GCM at rest (`ENCRYPTION_KEY` в env); минимальные scopes; OAuth и ввод ключа только в системном браузере по одноразовой ссылке.
- Webhook с secret token; CORS только для origin плагина; rate limit на `/api/*`.
- Тексты сообщений хранятся 48 ч (TTL), логи без содержимого сообщений и ключей.
- Отправка только после тапа + окно отмены 3 с; событие в календаре только из черновика `+cal`.

## 8. Ограничения платформы → решение
| Ограничение | Решение |
|---|---|
| Нет пушей в фоне, одно активное приложение | Очередь на бэкенде; при открытии сразу Inbox; SSE, пока открыто |
| Нет доступа к уведомлениям телефона | Telegram Business webhook |
| Нет STT на устройстве | STT-адаптер на бэкенде |
| Google Sign-In не работает в WebView | Pairing через бота + ссылки в браузер |
| Нет кириллицы в шрифте (проверить!) | Транслит для линз, оригинал в Telegram |
| Долгий тап может забрать ОС | Дубль в контекстном меню |
| Android может «усыпить» WebView | Состояние на бэкенде, токен в localStorage, холодный старт = Inbox |

## 9. Соответствие критериям
