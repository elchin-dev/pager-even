# Pager — спецификация MVP (v5, 24.11.2026)

> Рабочее название. Треки: **01 Messaging & News** + **04 AI Assistants & Work**, спецприз **Best Telegram integration**.
> **v5 (текущий объём):** режимы Urgent/All, диктофон → голосовое (без расшифровки и ИИ, подтверждение для коротких и длинных записей), конфликты с календарём («вы заняты»), бриф «пока тебя не было», онбординг без терминала, продакшен.
> Сняты из объёма (roadmap в README): автоответчик, фильтр тона, голос→текст с ИИ-полировкой, Флоу «проекты и приглашения», страница BYOK.
> Пошаговые промпты: `next-v5-plan-and-prompts.md` (в репо: `docs/NEXT-v5.md`).

## 1. Концепция в одной фразе

**AI-пейджер для Telegram на очках G2:** показывает только сообщения, которые требуют реакции, одной строкой на линзе, и даёт ответить за секунду: тапом по готовому AI-черновику, с учётом твоего Google Calendar, или короткой фразой голосом, которую ИИ превращает в нормальный ответ.

Питч для жюри: *«Прочитал — ответил — не достал телефон».*

### Чем отличаемся от существующих G2-приложений для Telegram
В экосистеме уже есть читалки/диктовалки (TeleGlance, even-messages, even-bridge и т.д.). Они переносят чат на очки «как есть». Pager делает другое:
1. **Триаж:** ИИ отсеивает шум, на линзу попадает «что нужно сделать», а не поток.
2. **Ответ в 1 тап:** 3 коротких черновика вместо диктовки.
3. **Межсервисное действие:** «Встретимся завтра?» → проверка Calendar → ответ со слотом + создание события.
4. **Официальный Telegram Business Bot API**, а не MTProto-сессия пользователя: мы не храним доступ к аккаунту, пользователь сам выбирает чаты и отключает бота в настройках Telegram.
5. **Конфликты:** «созвонимся завтра в 15:30» → «⚠ ты занят: Standup 15–16» + черновики с другим временем.

## 2. MVP: флоу Read & Write

### 2.0 Режимы и настройки

**Два режима ленты** (переключатель: пункт меню «Mode» на линзе + переключатель в настройках на телефоне):

| Режим | Что попадает в Inbox | Для кого |
|---|---|---|
| **Urgent** (по умолчанию) | `priority = urgent` или есть конфликт с календарём, **и** на сообщение можно ответить (есть черновики). Шум, «спасибо», стикеры, рассылки не показываются | На встрече, в дороге: «покажи только то, что горит» |
| **All** | Все входящие из подключённых чатов, по времени; срочные помечены `!`, конфликты `⚠` | Свободное время: общаешься со всеми |

Шапка Inbox: `URGENT · 2` или `ALL · 9 (2!)`, справа ближайшая встреча, если она в течение часа. Пустой Urgent: `No urgent · 7 in All`.

**Настройки** — в телефонном UI плагина (на линзе только переключатель режима), хранятся на сервере в `user_settings`:

| Настройка | Значения | По умолчанию |
|---|---|---|
| Режим ленты | Urgent / All | Urgent |
| Диктофон по долгому тапу | вкл / выкл | вкл |
| Предупреждения о конфликтах в Telegram | вкл / выкл | вкл |


### Флоу A: Триаж + ответ в 1 тап (ядро, обязателен)
1. Собеседник пишет в личку → бот получает `business_message` (webhook).
2. Бэкенд → LLM: приоритет, суть ≤ 40 символов, интент, 3 черновика на языке собеседника + версия для линзы ≤ 32 символов.
3. Пользователь открывает Pager → **Inbox** (только «нужен ответ», сверху срочные).
4. Тап → **Card**: кто, суть, 3 черновика. Свайп выбирает, тап отправляет (окно отмены 3 сек).
5. Отправка от имени пользователя: `sendMessage` + `business_connection_id`.

```
INBOX                               CARD
┌──────────────────────────────┐    ┌──────────────────────────────┐
│PAGER · 3 need reply          │    │Aziz K. · urgent              │
│> ! Aziz K.  KP by 17:00?     │    │Asks for the KP by 5pm today  │
│    Mom      Call tonight?    │    │> Yes, sending by 17:00       │
│    Dilnoza  Meet tomorrow?   │    │  Tomorrow morning ok?        │
│                              │    │  Will call you in 10 min     │
└──────────────────────────────┘    └──────────────────────────────┘
```

### Флоу B: Ответ с учётом календаря (вау-момент трека 04)
1. LLM помечает интент `schedule` («встретимся/созвонимся/когда удобно»).
2. Бэкенд берёт события из Google Calendar на 3 дня → считает 2–3 свободных слота в рабочие часы.
3. Черновики строятся из слотов: «Tomorrow 15:00 works», «Thu 11:00?».
4. Тап → отправка ответа **+ создание события** в Calendar («Meeting: Dilnoza»).
```
┌──────────────────────────────┐
│Dilnoza · meeting             │
│Free tomorrow afternoon?      │
│> Tomorrow 15:00 works  +cal  │
│  Tomorrow 17:00?       +cal  │
│  Thu 11:00 better?           │
└──────────────────────────────┘
```


### Флоу C: Диктофон по долгому тапу → голосовое сообщение
Без расшифровки, без ИИ, без фильтров: что сказал, то и ушло голосовым от твоего имени.
1. На Card: **долгий тап** = запись (держишь — пишет, отпустил — стоп), лимит 60 с (автостоп). Дубль в меню: «Record voice» (тап — старт, тап — стоп), если ОС заберёт долгий тап.
2. PCM с микрофона G2 → WAV → сервер → ffmpeg → OGG/Opus → `sendVoice` с `business_connection_id`. Аудио нигде не хранится.
3. Что после остановки записи — зависит от длительности (в очках нет динамика, прослушать запись нельзя, поэтому подтверждение — единственная страховка):

| Длина | Поведение |
|---|---|
| < 0,7 с | молча отменить, `Too short` (случайное касание) |
| 0,7–2 с | **без таймера**: `Voice 0:01 · short` → `Send` / `Discard` |
| 2–30 с | отсчёт: `Voice 0:07 · sending in 3 · 2×tap cancel` |
| > 30 с | **без таймера**: `Voice 0:42 · long` → `Send` / `Discard` |

На экране подтверждения автоотправки нет. Пороги — в конфиге.
```
┌──────────────────────────────┐   ┌──────────────────────────────┐
│● REC 0:05 · release to stop  │   │Voice 0:42 · long             │
└──────────────────────────────┘   │> Send                        │
                                   │  Discard                     │
                                   └──────────────────────────────┘
```

### Флоу D: Конфликты с календарём («вы заняты»)
1. Триаж извлекает из сообщения дату/время (`when`): «завтра в 3», «в четверг утром», «до пятницы» — относительно текущего времени и таймзоны пользователя (по умолчанию Asia/Tashkent). Интенты: `schedule` (встреча/звонок), `task` (сделать к сроку), `reply`, `info`.
2. Если `when` есть и Google подключён → проверка событий на этот интервал (длительность по умолчанию 60 мин) → `conflict = {title, start, end}` или null.
3. Конфликт:
   - на линзе строка Inbox `⚠ Aziz  Meet Thu 15:00?`, в Card `You: Standup 15-16`;
   - черновики с другим временем из свободных слотов: «I'm busy then. 17:00 works?» (+cal), «Tomorrow 11:00?» (+cal), «Let me check and get back»;
   - бот пишет **тебе** в Telegram: `⚠ Aziz: meeting Thu 15:00 — you have 'Standup' 15:00–16:00` (работает как пуш на телефон, даже когда плагин закрыт);
   - если плагин открыт — баннер на 3 с через SSE.
4. Нет конфликта: первый черновик «Yes, 15:00 works» (+cal создаёт событие на это время); для `task` с дедлайном — «Will do by Fri» (+cal ставит напоминание).
```
┌──────────────────────────────┐
│Aziz · ⚠ busy                 │
│You: Standup 15-16            │
│> Busy then. 17:00 works? +cal│
│  Tomorrow 11:00?       +cal  │
│  Let me check, get back      │
└──────────────────────────────┘
```

### Бриф «пока тебя не было» + ближайшая встреча
При открытии плагина, если с прошлого открытия прошло > 30 мин и есть новое: экран из 2 строк (`3 need reply · Aziz waits on KP` / `Next: Standup 15:00 (in 12m)`), тап → Inbox. В шапке Inbox — ближайшая встреча в пределах часа.

### Онбординг без терминала
Пользователь не трогает Railway, ключи и BotFather — сервер, бот и Google-клиент общие (multi-tenant). На телефоне мастер из 3 шагов с галочками: ① Open @bot (pairing) → ② «Профиль → Изменить → Автоматизация чатов → @bot → разрешить ответы» → ③ Connect Google Calendar (необязательно). Бот ведёт по тем же шагам, `/status` показывает чек-лист. Страницы `/privacy`, `/terms`.

### Roadmap (вне объёма, упоминаем в README)
Автоответчик-секретарь; фильтр тона (смягчение исходящих/входящих); голос → текст с ИИ-полировкой; проекты и отложенные приглашения в группы; страница BYOK (свой ключ Claude/Gemini/ChatGPT); Notion/Gmail.

## 3. Карта жестов (тачпад на дужке = кольцо R1)

| Экран | Свайп ↑/↓ | Тап | Двойной тап | Долгий тап |
|---|---|---|---|---|
| Inbox | перемещение по чатам | открыть Card | выход (`shutDownPageContainer(1)`) | — |
| Card | выбор черновика | отправить (окно отмены 3 с) | назад / пропустить | диктофон (удерживать) |
| Sending / Voice 2–30 с | — | — | **отмена** | — |
| Voice confirm (короткая/длинная) | Send ↔ Discard | выбрать | Discard | — |
| Brief | — | → Inbox | → Inbox | — |

Контекстное меню на линзе: «Mode: Urgent/All», «Record voice», «Skip», «Refresh». ОС может перехватить «тап + удержание», поэтому запись дублируется пунктом меню.


## 4. Раскладка экрана (576×288)

- Шапка: text-контейнер, y=0, h≈44: «кто · приоритет».
- Суть: text-контейнер, y≈44, h≈70: 1–2 строки.
- Действия: **list-контейнер** (нативная подсветка и прокрутка, до 20 пунктов × 64 символа), `isEventCapture: 1`.
- Итого 3 контейнера (симулятор принимает не больше 4).
- Обновления текста через `textContainerUpgrade`, смена экрана через `rebuildPageContainer` (меню пересылать каждый раз).
- В документированном шрифте нет кириллицы, неподдерживаемые символы молча пропадают → **слой транслитерации** для линз (ru/uz-кириллица → латиница). В Telegram уходит оригинал. Демо снимаем на английском.

## 5. Архитектура

```
 Telegram (собеседник)                          Google Calendar API
        │ личное сообщение                               ▲ события, слоты, конфликты
        ▼                                                │ refresh token (AES-GCM)
 Telegram Bot API ──webhook (secret header)──►  ┌─────────────────────────┐
        ▲                                        │ Backend (Node+Hono+TS)  │
        │ sendMessage / sendVoice                │ • grammY bot            │◄─► LLM (Gemini,
        │ (business_connection_id)               │ • triage / drafts / when│     адаптер провайдеров)
        └────────────────────────────────────────│ • conflicts / brief     │
  Бот → тебе: «⚠ ты занят» (пуш на телефон)      │ • ffmpeg WAV → OGG/Opus │
  Браузер: Google OAuth ────────────────────────►│ • pairing / onboarding  │
                                                 │ SQLite (Drizzle)        │
                                                 └──────────▲──────────────┘
                                                            │ HTTPS + Bearer deviceToken (+ SSE)
                                   ┌────────────────────────┴────────────┐
                                   │ Plugin: Vite + TS + even_hub_sdk     │
                                   │ (WebView в Even Realities App)       │
                                   │ • экраны: Brief/Inbox/Card/Voice     │
                                   │ • буфер PCM → WAV                    │
                                   │ • phone UI: онбординг + настройки    │
                                   └────────────────┬─────────────────────┘
                                                    │ BLE (SDK)
                                                 Even G2 / R1
```

### Стек
- **Plugin:** шаблон `evenhub-templates/minimal`, Vite + TypeScript, без фреймворка.
- **Backend:** Node 20 + TypeScript + Hono, grammY, SQLite (better-sqlite3) + Drizzle, zod, googleapis, ffmpeg (в Dockerfile). Railway: окружения staging и production, volume, постоянный HTTPS-домен.
- **AI:** Gemini через адаптер провайдеров (замена провайдера = смена env).

### Почему ИИ на сервере, а не в очках
- Telegram шлёт webhook на сервер, пока плагин закрыт → триаж и поиск конфликтов делаются **в момент прихода**, при открытии всё готово.
- Ключ не попадает на клиент; жюри не нужен свой ключ.

### Сопряжение (Pairing Code) и авторизация
1. Плагин при первом запуске: `POST /api/pair/start` → `{pairId, code}`. Линза: `Send 482913 to @<bot>`. Телефонный UI: кнопка-диплинк `t.me/<bot>?start=482913`.
2. Бот получает `/start 482913` (или код текстом) → связывает Telegram-пользователя с устройством. Код живёт 10 минут, одноразовый.
3. Плагин опрашивает `GET /api/pair/status?pairId=` → получает `deviceToken` → хранит в localStorage. В БД только SHA-256-хэш.
4. Бот присылает инструкцию: «Профиль → Изменить → Автоматизация чатов → @бот → выбрать чаты и разрешить ответы» (у Premium: Settings → Telegram Business → Chatbots). Приходит `business_connection` → сохраняем `connection_id`, `rights`.
5. `/google` в боте → одноразовая ссылка → **обычный браузер** → Google OAuth (`calendar.events`), `state` одноразовый → refresh token шифруется AES-256-GCM.
6. `/unpair` отзывает токен устройства и удаляет Google-токены.


### API бэкенда
| Метод | Назначение |
|---|---|
| `POST /tg/webhook` | апдейты бота; проверка `X-Telegram-Bot-Api-Secret-Token` |
| `POST /api/pair/start`, `GET /api/pair/status` | сопряжение |
| `GET /api/inbox?mode=urgent\|all` | лента с учётом режима: `{mode, counts, items}` |
| `GET /api/msg/:id` | карточка: суть, черновики, слоты, конфликт |
| `POST /api/msg/:id/send` | `{draftIndex}` или `{text}`; `+cal` создаёт событие |
| `POST /api/msg/:id/skip` | пометить «просмотрено» |
| `POST /api/msg/:id/voice` | `audio/wav` → ffmpeg → OGG/Opus → `sendVoice` |
| `GET /api/brief` | бриф и ближайшая встреча |
| `GET/PUT /api/settings` | настройки из §2.0 |
| `GET /api/onboarding` | статус 3 шагов подключения |
| `GET /api/stream` | SSE: `inbox`, `conflict` |
| `GET /auth/google/start?t=`, `/auth/google/callback` | OAuth в браузере |
| `GET /privacy`, `/terms`, `/health` | служебные |

Бот: `/start <code>`, `/google`, `/status`, `/help`, `/unpair`; апдейты `business_connection`, `business_message`.

### Модель данных (SQLite)
- `users` (id, tg_user_id, tg_name, business_connection_id, business_rights_json, tz, created_at) — с Bot API 9.0 вместо `can_reply` приходит объект `rights`
- `user_settings` (user_id, feed_mode: urgent|all, voice_enabled, conflict_alerts, last_opened_at, updated_at)
- `contacts` (id, user_id, tg_user_id, name, username, last_message_at)
- `devices` (id, user_id, token_hash, created_at, revoked_at)
- `pair_codes` (code, pair_id, user_id NULL, expires_at, used_at)
- `link_tokens` (token_hash, user_id, purpose: google, expires_at, used_at)
- `google_accounts` (user_id, email, refresh_token_enc, scope)
- `messages` (id, user_id, chat_id, tg_message_id, from_name, text, received_at, status: new|seen|replied|skipped, ai_json, expires_at)
- `actions` (id, message_id, type: reply|event|voice|conflict_alert, payload, created_at) — для voice только длительность, без аудио

## 6. ИИ
- Провайдер на сервере за адаптером `LlmProvider` (сейчас Gemini, `AI_DEFAULT_PROVIDER`); строгий JSON + zod, 1 ретрай, затем локальный фолбэк `buildFallbackTriage`.
- ИИ используется для: триажа, черновиков, извлечения времени (`when`), брифа. Диктофон ИИ не использует.
- Почему на сервере, а не в очках: триаж делается в момент прихода сообщения (плагин может быть закрыт), ключ не попадает на клиент, жюри не нужен свой ключ.

### Контракт LLM (триаж)
Вход: последние 3–5 сообщений чата, имя, текущее время и таймзона, свободные слоты, конфликт (если найден). Выход строго JSON:
```json
{
  "priority": "urgent|needs_reply|fyi|ignore",
  "intent": "reply|schedule|task|info",
  "gist": "Wants a call tomorrow 15:30",
  "lang": "ru",
  "when": {"start": "2026-11-26T15:30:00+05:00", "end": null, "allDay": false, "text": "завтра в 15:30"},
  "drafts": [
    {"text": "В 15:30 занят, в 17:00 удобно?", "lens": "Busy then. 17:00 works?", "slot": "2026-11-26T17:00:00+05:00"},
    {"text": "Может завтра в 11:00?", "lens": "Tomorrow 11:00?", "slot": "2026-11-27T11:00:00+05:00"},
    {"text": "Проверю и вернусь", "lens": "Let me check, get back", "slot": null}
  ]
}
```
`text` уходит в Telegram, `lens` показывается на очках (латиница, ≤ 32 символа). `conflict` считает сервер, не ИИ.

### Голос (клиент)
`audioControl(true, Glasses)` на начало удержания → копим `audioEvent.audioPcm` (s16le, 16 kHz, mono, ~100 мс чанки) → на отпускании `audioControl(false)` → WAV → правила длительности (Флоу C) → `POST /api/msg/:id/voice`. В симуляторе — микрофон компьютера (`--aid`).

## 7. Безопасность
- Все ключи только в env сервера (Railway variables); `.env` в `.gitignore`; в `plugin/` нет секретов.
- Нет MTProto-сессии: только подключение через «Автоматизацию чатов», видимое и отзываемое в Telegram.
- Device token: 32 случайных байта, в БД SHA-256; отзыв `/unpair`.
- Google refresh token: AES-256-GCM (`ENCRYPTION_KEY`); минимальные scopes; OAuth только в системном браузере по одноразовой ссылке.
- Webhook с secret token; CORS только для origin плагина; rate limit `/api/*`, дневной лимит ИИ-вызовов на пользователя.
- Тексты сообщений хранятся 48 ч (TTL); аудио не хранится; логи без содержимого сообщений.
- Любая отправка — только после тапа (окно отмены 3 с или явное подтверждение для коротких/длинных записей); событие в календаре только из черновика `+cal`.

## 8. Ограничения платформы → решение
| Ограничение | Решение |
|---|---|
| Нет пушей в фоне, одно активное приложение | Очередь на сервере; предупреждения о конфликтах приходят ботом в Telegram; бриф при открытии; SSE пока открыто |
| Нет доступа к уведомлениям телефона | Telegram Business webhook |
| Нет динамика в очках | Подтверждение для коротких/длинных голосовых вместо прослушивания |
| Google Sign-In не работает в WebView | Pairing через бота + ссылки в браузер |
| Нет кириллицы в шрифте | Транслит для линз, оригинал в Telegram |
| Долгий тап может забрать ОС | Дубль «Record voice» в меню |
| Android может «усыпить» WebView | Состояние на сервере, токен в localStorage, холодный старт = Brief/Inbox |

## 9. Соответствие критериям
| Критерий | Чем закрываем |

## 11. Риски и фолбэки
1. **Кириллица не рисуется** → транслит.
2. **CORS/whitelist в WebView** → проверка на прод-домене.
3. **Задержка LLM** → триаж в webhook, не при открытии.
4. **ffmpeg на Railway** → ставим в Dockerfile, `/health` проверяет; при сбое на линзе `Voice not sent · tap retry`.
5. **Долгий тап перехвачен ОС** → «Record voice» в меню.
6. **ИИ неверно понял время** → конфликт только предупреждает, ничего не отправляет сам; в Card видно, какое время распознано.
7. **Google в режиме Testing** → перевести в In production (без верификации, до 100 пользователей, экран «unverified app»), иначе токены живут 7 дней.
8. **Деплой ломает демо** → staging для экспериментов, тег `v1.0-submission`, production не трогаем после записи видео.
